# Obsidian「行号区拖动多选」插件 —— 可行性分析与设计方案

> 目标：让 Obsidian 编辑器像 VS Code 一样，在行号区（gutter）按下鼠标拖动即可整行、连续地选中多行。

---

## 0. 结论先行

| 判定项 | 结论 |
| --- | --- |
| 技术可行性 | **完全可行**。Obsidian 官方提供 `registerEditorExtension()` 注入 CodeMirror 6 扩展，CM6 的 gutter 本身就是一等公民，事件回调直接给出 `BlockInfo`（含 `from/to/top/height`）[citation:7][citation:26] |
| 是否需要改 Obsidian 内核 | 不需要。纯插件层实现，不 patch、不用 CSS hack 兜底核心逻辑 |
| 是否有非公开 API 依赖 | 仅 `view.editor.cm`（取 EditorView）是非公开属性，但 Obsidian 官方文档自己就在示例中这么用（配 `@ts-expect-error`）[citation:1]；本方案只在「设置变更后热更新」这一处用到它，核心交互不依赖 |
| 主要风险 | Live Preview 折叠区 / 嵌入块的行映射、表格内嵌编辑器、Vim 模式、移动端触摸冲突 —— 均为**可规避或可降级**项，非阻塞 |
| 社区已验证 | 同类插件 `line-multi-selector`、`Hybrid Line Numbers` 已上线并跑通同一技术路径[citation:29][citation:35]，说明不存在未知的黑盒限制 |
| 工作量估算 | 可用版本 3–5 人日；打磨到社区发布标准 8–10 人日 |

一句话：**这是 CM6 能力范围内的"补齐交互"型需求，不是逆向工程。** 真正的难点不在"能不能选中"，而在"折叠、嵌入块、多编辑器实例下选中范围是否精确"。

## 1. 需求定义：把 VS Code 的行为逐条对齐

| 交互 | VS Code 行为 | 本插件目标 |
| --- | --- | --- |
| 单击行号 | 选中整行（含行尾换行符） | 一致，含 EOL，可配置[citation:35] |
| 按住左键上下拖动 | 以行为单位连续扩展选区 | 一致；向上拖时 anchor 在起始行行尾、head 在末行行首（方向与 VS Code 一致，便于后续 Shift+方向键微调） |
| 拖出编辑器上下边缘 | 笔记自动滚动，可连续选超出一屏 | 一致，速度与超出距离成正比 |
| Shift + 点击行号 | 从当前锚点扩展到该行 | 一致 |
| Ctrl/Cmd + 点击行号 | 追加/取消一行选区（多光标） | 追加整行选区并 toggle；依赖 `EditorState.allowMultipleSelections` |
| Alt/Option + 拖动 | 列（矩形）选择 | **P2 可选**，CM6 已有 `rectangularSelection` 可参考[citation:45] |
| 拖拽中按 Esc | 取消并回滚到按下前的选区 | 一致 |
| 视觉反馈 | 被选中行的行号底色高亮 | 用 `gutterLineClass` 精确高亮，非"整列染色" |

## 2. 现状调研：技术底座核实结果

以下是动手前已核实的事实（不是推测）：

1. **Obsidian 的编辑器就是 CodeMirror 6**。插件可通过 `Plugin.registerEditorExtension()` 注册 CM6 扩展，作用于当前及后续所有编辑器实例，随插件卸载自动清理[citation:7][citation:2]。
2. **取 EditorView**：`view.editor.cm` 是 CM6 的 `EditorView`。官方开发者文档在"与编辑器扩展通信"一页直接给出该写法并标注 `@ts-expect-error`[citation:1]。
3. **行号列的 DOM**：`.cm-gutters > .cm-gutter.cm-lineNumbers > .cm-gutterElement`，每个 element 只有 `style.height/marginTop`，**不带行号或位置的 data 属性** —— 所以不能从 DOM 反推行号，必须走坐标映射或 gutter 事件回调。Obsidian 是否在用原生行号，可由 CSS 片段 `.cm-gutters .cm-gutter.cm-lineNumbers` 生效反证[citation:33]。
4. **CM6 的 `lineNumbers()` 默认没有任何 mousedown 行为**（读源码确认：其 `domEventHandlers` 默认取自空配置）。这既是好消息（没有默认行为要覆盖），也解释了为什么这类插件要自己实现"点击选整行"。自定义 gutter 可通过 `domEventHandlers` 拿到签名 `(view, line: BlockInfo, event) => boolean`[citation:26]。
5. **行定位 API**：`view.lineBlockAtHeight(height)`、`view.viewportLineBlocks`、`view.documentTop`（高度均相对文档顶部）[citation:15]；Obsidian 官方迁移说明也确认这批 API 取代了旧的 `blockAtHeight/viewportLines`[citation:27]。旧版本可降级到 `view.posAtCoords({x, y})`[citation:17]。
6. **是否已有同类插件**：有，且已验证路径可行——
   - `line-multi-selector`：点击/Ctrl 切换/Shift 连续/拖动选块，依赖用户先打开"显示行号"[citation:29]；
   - `Hybrid Line Numbers`：自绘行号列并隐藏原生列，支持拖动逐行选、拖出边缘自动滚动、Shift 扩展、Alt 追加、折叠区整块选中、Vim 兼容[citation:35][citation:34]。

**差异化判断**：重复造一个一样的轮子价值不大。真正值得做的三个差异点——① 不接管行号渲染、零视觉侵入（复用原生行号列）；② 折叠/嵌入块/表格等边界的选区精度；③ 与 Vim 模式、多光标、Canvas 卡片的兼容处理。

## 3. 可行性逐项分析

### 3.1 事件从哪来（可行，两条路径）

| 路径 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. Hook 原生行号列** | 在 `view.dom` 上以 **capture 阶段**监听 `pointerdown`，用 `event.target.closest('.cm-lineNumbers')` 限定命中范围 | 零视觉改动、不接管渲染、与主题天然一致；代码量小 | 依赖用户在 设置 ▸ 编辑器 打开「显示行号」[citation:39]；需自己做坐标→行映射 |
| **B. 自绘行号列** | 注册 `gutter({class, lineMarker, domEventHandlers})`，事件回调**直接拿到 `BlockInfo`** | 不依赖系统设置；可做相对行号、hover 态等增强；行区间精确 | 要处理"两列行号"（用 body class + CSS 隐藏原生列）；要自己做主题适配 |

**结论：默认走 A，把 B 作为设置项。** 两者共用同一套拖拽状态机与选区算法，切换成本被限制在一个工厂函数里。

选 capture 而不用 `EditorView.domEventHandlers` facet 的原因：facet 绑在冒泡阶段，会晚于 gutter 自身与其它插件的 handler；capture 能确定性地 `preventDefault + stopPropagation`，避免浏览器启动原生文本选择。

### 3.2 坐标 → 行（可行，三档降级）

```
height = clientY - view.documentTop
① view.lineBlockAtHeight(height)            // CM6 6.26+，正确处理折叠与 block widget
② 在 view.viewportLineBlocks 中二分/线性查找  // 同批引入，稳妥
③ view.posAtCoords({x: 内容区左侧, y}) → doc.lineAt(pos)  // 兜底，老版本也能跑
```

拖到编辑器外时按"钳制到首/末行"处理，配合自动滚动即可覆盖 VS Code 的完整体验。

### 3.3 选区表达（可行）

- 单行：`EditorSelection.range(line.from, line.to + (includeEOL ? 1 : 0))`，末行不吞换行符。
- 拖拽：按下时记录 anchor 行块，`pointermove` 中只在**行块变化时**才 dispatch（避免每像素一次事务）。
- 多选区：必须注入 `EditorState.allowMultipleSelections.of(true)`，否则 CM6 会把追加的选区合并掉[citation:47]。
- 追加/Ctrl 分支统一丢掉纯光标 range，避免复制时带上一个看不见的空选区。

### 3.4 视觉反馈（可行）

用 `gutterLineClass` facet + 一个 `StateField` 记录当前选区区间，给被选中的行块挂 `elementClass`。这条路子只加 class、不重绘内容，对主题无侵入，也符合官方对该 facet "只提供 elementClass、不要 toDOM" 的约束。

### 3.5 真正的难点（不阻塞，但决定口碑）

| 难点 | 为什么难 | 应对 |
| --- | --- | --- |
| Live Preview 的折叠区 | 折叠后隐藏文本仍在文档里，"一行"实际是一个区间 | 用 `BlockInfo.from/to`，天然覆盖折叠整块；实测确认后再决定是否额外展开 |
| 嵌入块 / 块 widget | 视觉行与源码行不对齐，widget 可能占多个行块 | 以 `BlockInfo` 为准而非 `doc.line()`；`lineBlockAtHeight` 会返回 widget 所在块 |
| 表格单元格内嵌编辑器 | Obsidian 在光标进入单元格时会创建**内层 EditorView** | 注册扩展时按场景白名单（普通 Markdown / Canvas 卡片）启用，表格内嵌视图直接跳过 |
| Vim 模式 | Vim 扩展维护自己的 selection/visual 状态 | 选区一律走 `view.dispatch({selection, userEvent})`，让 Vim 扩展自己观察；如有偏差再走其 API 同步 |
| 移动端 | 没有 hover，触摸拖动会与滚动/长按冲突 | 首版 `isDesktopOnly: false` 但移动端默认仅"点击选整行"，拖动需长按触发或直接关闭 |
| 阅读模式 | 没有 CodeMirror 实例 | 不适用，无需处理 |

## 4. 方案设计

### 4.1 分层架构

```
┌─ 输入层 ──────────── gutter 事件源（可插拔）
│   A: capture 监听原生 .cm-lineNumbers      B: 自绘 gutter 的 domEventHandlers
│                     ↓ 统一产出 LineBlock { from, to }
├─ 定位层 ──────────── blockAtClientY(view, y, clamp)   三档降级
├─ 计算层（纯函数，可单测）── selection.ts
│   rangeForLine / rangeForDrag / rangeForShift / toggleLineRange / addRange
├─ 状态机层 ─────────── DragState：anchor、base、mode、lastBlock
│   window pointermove/up + rAF 自动滚动 + Esc 回滚
├─ 反馈层 ──────────── StateField + gutterLineClass → .cm-lds-selected
└─ 配置层 ──────────── Settings + Compartment 热重配 + SettingTab
```

**关键设计取舍**：把选区计算做成**不依赖 DOM 的纯函数**（输入 `EditorState` + 两个 `LineBlock`，输出 `SelectionRange`），因此它可以在 Node 里跑单测 —— 这是整套方案里最容易出错、也最值得测试的部分。

### 4.2 目录结构（已落地的骨架）

```
obsidian-line-drag-select/
├── manifest.json            # id/name/minAppVersion 1.4.0
├── package.json / tsconfig.json / esbuild.config.mjs
├── styles.css               # 自绘模式下隐藏原生列 + 选中行高亮
├── src/
│   ├── selection.ts         # 纯逻辑：行块 → 选区（已单测）
│   ├── gutter.ts            # 事件源、行定位、拖拽状态机、自动滚动、高亮
│   ├── settings.ts          # 配置项与默认值
│   └── main.ts              # Plugin 装配、Compartment 热重配、设置面板
└── tests/selection.test.ts  # 11 条用例，已全部通过
```

### 4.3 核心逻辑（节选）

```ts
/** 拖拽：向下吃行尾，向上吃行首，anchor/head 方向与 VS Code 一致 */
export function rangeForDrag(state, anchor, current, opts) {
  if (current.from >= anchor.from)
    return EditorSelection.range(anchor.from, blockEnd(state, current, opts));
  return EditorSelection.range(blockEnd(state, anchor, opts), current.from);
}

/** 行定位：三档降级，拖出边界时钳制到首/末行 */
const height = clientY - view.documentTop;
if (typeof view.lineBlockAtHeight === "function") return view.lineBlockAtHeight(height);
// 否则 viewportLineBlocks → posAtCoords

/** 只有在跨行时才 dispatch，避免高频事务 */
if (sameBlock(block, d.lastBlock)) { scheduleAutoScroll(); return; }
```

自动滚动采用 `requestAnimationFrame` 循环：每帧按超出边缘的距离算 `scrollTop` 增量，滚动后用**同一个 clientY 重新定位行块**（滚动会改变 y 与行的对应关系），再扩展选区。

### 4.4 交互矩阵

| 修饰键 | pointerdown | 拖动 |
| --- | --- | --- |
| 无 | 选中整行，记为 anchor | 连续扩展 |
| Shift | 从既有 anchor 扩展到该行 | 同上（以 anchor 为轴） |
| Ctrl/Cmd | toggle 该行选区 | 追加一段连续选区 |
| Esc（拖动中） | — | 回滚到按下前选区并清理高亮 |

## 5. 风险清单与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| `editor.cm` 非公开 API，未来可能变动 | 中 | 仅用于设置热更新；核心交互走 `registerEditorExtension`，并做 try/catch |
| CM6 版本差异（`lineBlockAtHeight` 缺失） | 中 | 三档降级，已在代码中实现 |
| 与其它 gutter 插件（折叠箭头、断点式 gutter）抢事件 | 中 | `closest('.cm-lineNumbers')` 精确限定；`Prec.highest` 提权 |
| 长文档高频 dispatch 掉帧 | 低 | 跨行才 dispatch；自动滚动走 rAF；高亮用 StateField 而非重绘 DOM |
| 表格内嵌 / Canvas 卡片误触发 | 中 | 按场景白名单启用，异常环境直接 no-op |
| 移动端触摸与滚动冲突 | 中 | 首版移动端只保留点击选行 |
| 用户没开行号导致"插件没反应" | 低 | 设置面板说明 + 内置「检查行号是否已开启」命令 |

## 6. 验证方案

### 6.1 已完成的自动化验证（本次已跑通）

- `tsc --noEmit` 类型检查通过；
- `esbuild` 生产构建产出 `main.js`（约 15 KB）；
- 选区计算单测 **11/11 通过**，覆盖：单击含/不含 EOL、向下拖、向上拖、原地按下、Shift 双向扩展、Ctrl 追加与 toggle、多选区按文档顺序规范化。

样例（doc = `aaa\nbbb\nccc\nddd`）：

```
单击第2行（含换行符）        -> [4, 8]
从第2行向下拖到第4行         -> [4, 15]
从第4行向上拖到第2行         -> [15, 4]   ← anchor 在右、head 在左，方向正确
锚点在文末，Shift 点到第2行  -> [15, 4]
追加第3行 → 再 toggle        -> [[8,12]] → [[8,8]]
```

### 6.2 真机验收清单（建议在 Obsidian 中逐条走）

1. Live Preview / 源码模式分别验证点击、上下拖动、跨屏自动滚动；
2. 折叠标题与 callout 后，点击折叠行号是否选中整块；
3. 含嵌入块（`![[note]]`）、代码块、长表格的行号对齐是否准确；
4. 与 Vim 模式、多光标插件、Templater 等共存；
5. 分屏/多标签同时打开、切换笔记、插件热重载不残留监听；
6. 万行级长文档拖动时的帧率与内存。
